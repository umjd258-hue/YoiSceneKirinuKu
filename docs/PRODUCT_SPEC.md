# PRODUCT_SPEC.md

# 良いシーン切りぬく〜よ

MacBook Air M4 / 32GB / 最新macOS向け、自分専用・完全ローカル。

## 目的
SDカード等の外部ストレージにあるアニメ・ドラマ等の動画（目安20分〜2時間半）から、
「誰が・どこで話しているか」を解析し、人物ごとの発話候補を提示する。

ユーザーが候補を確認して選択した場面だけを、高品質MP4として保存する。

## 基本パイプライン
動画
→ Preflight
→ 解析用16kHz mono WAV
→ VAD
→ 候補区間生成
→ Speaker Embedding
→ 登録人物比較
→ 人物一致/人物不明
→ 品質評価
→ `result.json`
→ SwiftUI結果画面
→ AVPlayer確認
→ 保存対象選択
→ 高品質切り抜き
→ `.partial`
→ 検証
→ 正式MP4

## 人物登録
- 1人物に複数sampleを登録可能。
- sampleは音声ファイルまたは動画から選択可能。
- 動画sampleの場合は指定区間から音声を抽出して使用する。
- Speaker Embeddingを生成・保存する。
- 複数sample統合方式は技術検証で決定する。
- 登録品質が不足する場合はfail-closed。
- 一致度不足は「人物不明」。

## AI閾値
人物一致閾値、人物不明判定、「高い/中程度」等への変換は、
代表性のあるラベル付き実人物データで検証して決定する。
人工音声だけの結果を実人物閾値へ転用しない。

## 品質
対象人物の声の明瞭さ、他人物の同時発話、BGM、SE、雑音、発話切れ等を考慮する。
完全分離を保証しない。
最終保存判断はユーザーが行えるようにする。
追加modelなしで自動観測できないBGM、SE、他話者、加工音声等は推測せず、optionalな人手補助評価を自動featureと分離して使用する。人手補助評価がない候補は品質を安全側の△とする。

## 安全
- 元動画を上書き/削除しない。
- 完成済み成果物を勝手に削除しない。
- 動画/音声/Embeddingを外部送信しない。
- 外部APIを製品処理に必須としない。

## 文字起こし
現行版では文字起こし/ASRを必須処理にしない。
人物判定はVAD・Speaker Embedding・speaker matchingを主経路とする。
ASR追加は独立した仕様変更として扱う。

## 完成判定
製品全体の完成条件は `docs/ACCEPTANCE_CRITERIA.md` を正本とする。
動画入出力、cleanup、人物管理、privacy、dependency versionの詳細は各専用正本を参照する。

## 初期版スコープ固定
`docs/ORIGINAL_SCOPE_CONTRACT.md` を正本とする。
正式入力はMP4を基本とし、解析と保存を分離する。
MVPは結果一覧でユーザーが明示的に選択した1候補だけを書き出す。一括選択・一括exportはMVP後とする。
人物登録の `source.wav` は再生成元資産として保護する。
品質表示は原則 ◎ / ○ / △ の3段階＋簡潔な理由codeとする。
