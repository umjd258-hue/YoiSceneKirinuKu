# 「良いシーン切りぬく〜よ」操作画面・UI実装仕様書

MacBook Air M4・メモリ32GB向け  
macOS専用／SwiftUI版  
完全ローカル／軽量性重視／安定性重視／自分専用

## 1. 目的と優先順位

本仕様書は「良いシーン切りぬく〜よ」の操作画面をSwiftUIで実装するための仕様を定める。

参考デザイン画像から、白基調、青い主要操作、角丸カード、十分な余白、人物ごとの小さな色分け、左右分割レイアウト、SF Symbolsなどの視覚要素を参考にする。

具体的な参考画像と「参考にする／しない」の判断は `design/DESIGN_REFERENCE.md` にまとめる。UI実装時は該当画面の説明を確認する。

画像に描かれていても、本体仕様に存在しない機能は勝手に実装しない。

優先順位:

1. `PRODUCT_SPEC.md`
2. 本 `UI_SPEC.md`
3. `design/DESIGN_REFERENCE.md`
4. `../reference-images/` の参考画像

## 2. UIの中心思想

基本思想は「今、その工程で必要な操作だけを見せる」。

内部でVAD、Speaker Embedding、FFmpeg、Python、JSON Lines等を利用しても、通常画面ではユーザーに意識させない。

曖昧な状態を完成として表示しない。

- 「たぶん成功した」→ 完了扱いしない。
- 「保存要求を出した」→ 保存済み扱いしない。
- 「停止要求を出した」→ 停止済み扱いしない。

正式な成果物・状態を確認してから「完了」「保存済み」「停止しました」等を表示する。

未知schema、壊れた必須JSON、未知の通信eventを推測で正常処理しない。必要な正式データを検証できない場合は、完了画面へ進めず、安全なユーザー向けエラーを表示する。

## 3. 初期版の主要画面

主要画面は4つ。

1. `HomeView`
2. `AnalysisView`
3. `ResultsView`
4. `CharactersView`

必要に応じて小さなSheet / Popoverを使用する。
独立した設定画面は作らない。

## 4. 共通デザイン

macOSネイティブアプリとして自然に見えるデザインとする。

- SwiftUI標準部品とSF Symbolsを優先。
- 独自UI部品を必要以上に作らない。
- 背景は白または非常に薄いグレー。
- 大きなカードは白。
- 薄い境界線または必要最小限の影。
- 主要操作: 青。
- 成功: 緑。
- 注意: オレンジ。
- エラー: 赤。
- 人物不明等の中立状態: グレー。
- 赤は通常操作に使わず、エラー・削除確認等に限定。

### カード

- 角丸
- 十分な内側余白
- 薄い境界線
- シンプルなアイコン
- 強い影・過剰なガラス効果・カードの多重化を避ける

# HomeView

## 5. 役割

ホーム画面の目的は次の3操作だけ。

1. 動画を選ぶ
2. 人物を選ぶ
3. 解析開始

作品名、保存先、品質モード、AI閾値等は表示しない。

## 6. 基本構成

```text
良いシーン切りぬく〜よ
動画・音声は外部へ送信しません

┌─────────────────────────────┐
│ 動画                        │
│ episode01.mp4               │
│ 24分12秒                    │
│                     [変更]  │
└─────────────────────────────┘

┌─────────────────────────────┐
│ 探す人物                    │
│ ● コナン  ● 蘭  ● 灰原     │
│ 3人                         │
│                     [変更]  │
└─────────────────────────────┘

         [ ▶ 解析を開始 ]
```

## 7. 動画未選択

動画カード内に「動画を選んでください」と表示する。
解析開始ボタンはdisabled。

## 8. 動画選択とPreflight

初期版はMP4のみ。
選択後、すぐ本解析を開始せず軽いPreflightを行う。

確認中は動画カード内だけを「動画を確認しています…」にする。
アプリ全体をローディング状態にしない。

### 成功

表示は静かにする。

```text
episode01.mp4
24分12秒
```

大きな「正常です」は表示しない。

### 失敗

例:

```text
⚠ この動画は解析できません
音声トラックが見つかりません
```

FFmpeg等の技術エラー文字列は表示しない。
解析開始はdisabled。

Preflightのerror codeとユーザー向け文言は次のとおりとする。括弧内の内部codeや技術例外は画面へ表示しない。

| error code | ユーザー向け文言 |
|---|---|
| `invalid_request` | 動画を確認できませんでした |
| `unsupported_file_type` | MP4ファイルを選んでください |
| `input_not_found` | 選択した動画が見つかりません |
| `input_not_readable` | この動画を読み込めません |
| `probe_not_started` | 動画を確認できませんでした |
| `probe_timed_out` | 動画の確認に時間がかかりすぎました |
| `probe_failed` | この動画は解析できません |
| `invalid_probe_output` | 動画情報を確認できませんでした |
| `video_stream_missing` | 映像トラックが見つかりません |
| `audio_stream_missing` | 音声トラックが見つかりません |
| `invalid_duration` | 動画の長さを確認できません |
| `protocol_error` | 動画の確認処理で問題が発生しました |
| `internal_error` | 動画を確認できませんでした |

未知のerror codeは成功扱いせず、`internal_error` と同じ一般文言で失敗表示する。診断情報はUIへ出さない。

## 9. 人物表示

ホームには選択中の人物だけをチップ表示する。
登録人物すべてを並べない。

例:

```text
● コナン  ● 蘭  ● 灰原
```

## 10. 人物選択シート

「変更」でSheetを開く。

```text
人物を選ぶ
☑ コナン
☑ 蘭
☐ 灰原
☐ 小五郎

[キャンセル] [決定]
```

Sheet内の選択は一時状態とし、「決定」でホームへ反映する。
このSheet内では人物編集を行わない。

## 11. 人物未登録

```text
まだ人物が登録されていません。
最初に、探したい人物の声を登録してください。

[人物を登録]
```

解析開始はdisabled。

## 12. 解析開始条件

少なくとも以下をすべて満たした場合だけ有効。

- 動画Preflight成功
- 人物が1人以上選択済み
- 必要なAIモデルが存在
- Mac側の作業領域を利用可能
- Service層が別の解析プロセスまたは排他所有者が存在しないと確認できる

保存先は条件に含めない。

## 13. 解析開始直後

ボタン押下だけで成功扱いしない。
解析開始ボタンを無効化し「解析の準備をしています」へ移行する。
事前確認成功後に本解析を開始する。

# AnalysisView

## 14. 基本構成

情報を増やしすぎない。

```text
解析中
人物を確認しています
42 / 128

✓ 動画を準備
✓ 発話を探す
● 人物を確認
○ 音声品質を確認
○ 結果を整理

[停止]
```

## 15. UI上の工程

5段階固定。

1. 動画を準備
2. 発話を探す
3. 人物を確認
4. 音声品質を確認
5. 結果を整理

内部の細かな処理は通常UIへ出さない。

## 16. 進捗

信用できる実数を使う。

例:

```text
人物を確認しています
42 / 128
```

時間基準が自然な工程では:

```text
12分31秒 / 24分12秒
```

信用できない総合「58%」等は初期版では表示しない。

## 17. 表示しない情報

- CPU使用率
- メモリ使用率
- 推定残り時間
- 全体％
- 動画プレビュー
- 音声波形
- リアルタイム人物タイムライン
- 詳細処理ログ
- AI内部スコア
- 一時停止ボタン

## 18. 停止

「停止」ボタンを用意する。一時停止は作らない。

押下直後:

```text
安全に停止しています…
安全に停止できる状態を確認しています。
```

停止ボタンはdisabled。
停止要求後に新しい通常progressが届いても通常進捗表示を更新しない。

Python処理が実際に停止したことを確認後:

```text
解析を停止しました
完成済みの処理は残っています。

[続きから解析]
[ホームへ戻る]
```

「続きから解析」は正式完成済み工程が存在する場合だけ表示する。

元動画のSource fingerprintが一致しない場合や、正式完成済み工程を検証できない場合は「続きから解析」を表示しない。

停止要求後は、プロセス停止に加えて停止後状態を検証してから停止完了表示へ進む。partialしか存在しない工程を完了済みとして表示しない。

停止完了を通信上どの形式で表すかは未決定とする。既存の基本3イベントとの整合性を保ち、第14開始前までに `ARCHITECTURE.md` で正式決定する。UI実装時に独立イベントを推測で追加しない。

# ResultsView

## 19. 役割

「候補を見る → 保存する候補を選ぶ → 保存」の画面。
動画編集画面にはしない。

## 20. 基本構成

左側: 人物別候補一覧。  
右側: 動画プレビューと詳細。  
下部: 保存対象件数と保存ボタン。

```text
解析結果 18件
┌────────────────────┬─────────────────────────┐
│ コナン 8件         │                         │
│ ☑ 00:03:12 4秒 ◎   │      動画プレビュー     │
│ ☑ 00:08:41 6秒 ○   │                         │
│ ☐ 00:11:20 3秒 △   │          ▶              │
│                    │                         │
│ 蘭 5件             │ コナン                  │
│ ☑ ...              │ 00:03:12 - 00:03:16    │
│                    │ 人物一致：高い          │
│ ▶ 人物不明 4件     │ 品質：◎ とても良い     │
└────────────────────┴─────────────────────────┘
14件を選択中                [14件を保存]
```

## 21. グループ

人物単位でまとめる。
人物内は元動画の時間順。
「人物不明」は別グループで、初期状態では折りたたむ。

## 22. 一覧項目

一覧には原則以下だけ。

- 採用チェック
- 開始時刻
- 長さ
- 品質

人物名はグループ見出し。
終了時刻や人物一致度は右詳細へ表示。

## 23. 品質

3段階。

- ◎ とても良い
- ○ 良い
- △ 要確認

星5段階は使用しない。

## 24. 人物一致

生スコアを本人確率として表示しない。

例:

- 人物一致：高い
- 人物一致：中程度

「96％本人」等は禁止。

人物一致度と音声品質は別の概念として表示する。「人物不明」は音声品質の「△ 要確認」と同義ではなく、人物不明候補にも独立した品質表示を持たせてよい。

## 25. 品質理由

必要時のみ簡単に表示する。

例:

- 背景音がやや強い。
- 声が小さい。
- 音割れがあります。
- 短い発話です。

内部reason codeからユーザー向け文言へ変換する。

## 26. 初期チェック

- ◎: ON
- ○: ON
- △: OFF
- 人物不明: OFF

## 27. 初期版で行わない編集

- 人物の手動変更
- 開始・終了位置の手動編集
- トリム
- 候補削除
- 動画加工
- 音声加工

不要候補はチェックを外すだけ。

## 28. 動画プレビュー

AVPlayer / AVFoundationを使用。
Pythonは担当しない。
元動画から選択候補の範囲を直接再生する。

候補選択時は開始位置へseekするが、自動再生しない。
▶操作時だけ再生する。

AVPlayerは基本1つ。
候補変更時は前候補の再生を停止する。
observerを増殖させない。

## 29. 結果0件

エラー扱いしない。

```text
今回は条件に合う場面が見つかりませんでした。

[ホームへ戻る]
```

# CharactersView

## 30. 基本構成

左側: 人物一覧。  
右側: 選択人物の登録音声。

```text
人物
コナン 4件
蘭     3件
灰原   5件
----------------------------
灰原
登録音声
▶ episode01.mp4   7秒
▶ episode03.mp4   8秒
▶ episode05.mp4   6秒

[＋ 音声を追加]

合計 38秒
[人物を削除]
```

## 31. 人物一覧項目

表示:

- 人物名
- 登録音声件数

表示しない:

- 人物96％等のスコア
- 最終更新日時
- メモ
- AI内部スコア

## 32. 新規人物と登録音声追加

人物登録UIは、次の別工程として扱う。

- 第7A: 新規人物登録UI
- 第7B: 既存人物への登録音声追加UI

区間選択UIを共用してよいが、新規人物全体の登録と既存人物への新sample追加では、確定対象と失敗時の影響範囲を区別する。

### 新規人物

指定項目:

- 人物名
- 人物登録用動画
- 本人が話している区間

登録処理が完全成功するまで正式人物として一覧へ出さない。

### 既存人物への登録音声追加

新sampleの登録処理が完全成功するまで、正式な登録音声件数へ反映しない。追加に失敗しても既存人物と既存sampleを変更しない。

## 33. 人物登録用動画

初期版ではMP4から登録音声を作る。
ユーザーが本人だけが話している区間を選択する。

## 34. 人物音声区間選択

```text
人物の声を追加

episode01.mp4

[       動画プレビュー       ]

       [−5秒] [▶] [+5秒]

現在位置 00:12:14

開始 00:12:14
[現在位置を開始に]

終了 00:12:21
[現在位置を終了に]

[選択範囲を再生]

本人だけの声がはっきり聞こえる場面を
選んでください。

[キャンセル]
[この音声を追加]
```

操作は以下程度に限定する。

- 標準再生
- −5秒
- ＋5秒
- 現在位置を開始に設定
- 現在位置を終了に設定
- 選択範囲を再生

高度な動画編集UIは作らない。

## 35. 品質案内

「できるだけ、本人だけの声がはっきり聞こえる場面を選んでください。」

他人の声混入を完全自動検出できると誤解させる表現をしない。

## 36. 登録済み音声再生

人物管理画面では元動画ではなく、保存済み `source.wav` を再生する。

## 37. 最後の登録音声

人物に登録音声が1件しかない場合、その1件だけを直接削除できない。
削除する場合は人物そのものを削除する。

## 38. 人物削除

明示確認を行う。

```text
「灰原」を削除しますか？
登録音声5件も削除されます。
この操作は元に戻せません。

[キャンセル]
[削除]
```

解析中は人物削除不可。

解析開始要求中、停止要求中、保存中など、人物データと競合する状態でも人物削除を許可しない。削除ボタン押下だけで削除済み表示にせず、第8Cで定める正式削除処理の成功確認後にUIへ反映する。

# 保存UI

## 39. 保存開始

Resultsで「○件を保存」を押した時だけ保存工程へ入る。

## 40. 保存設定Sheet

最初の保存時だけ作品名・保存先・保存件数を確認する。

```text
保存

作品名
[ 名探偵コナン ]

保存先
SDCARD / Clips_Output
[変更]

14件を保存します

[キャンセル]
[保存]
```

作品名と保存先はHomeには置かない。

ファイルシステム上危険な文字は安全な名前へ変換するが、表示名は必要以上に変更しない。

前回保存先を初期値として利用してよい。

## 41. 保存中

Results画面を維持しOverlayを表示する。

```text
保存しています
7 / 20
コナン

[保存を中止]
```

保存中は以下を不可にする。

- AVPlayer再生
- 候補チェック変更
- 新しい保存開始
- 人物編集

## 42. 保存中止

「保存を中止」押下時は、現在の1クリップを安全に完了後、次を開始しない方式を有力候補とする。
最終挙動は技術検証後に確定する。

## 43. 保存先切断

保存先が消えた場合は保存を中断する。

```text
保存を中断しました
保存先が見つかりません。
6件は保存済みです。
解析結果はMacに残っています。

[再確認]
[後で保存]
```

再接続後に自動保存再開しない。

正式保存とsave_state更新が成功した候補だけ「保存済み」と表示する。

保存処理は完成MP4へ直接書き込まず、partialへの書込み、完了、検証、正式化、save_state更新の順を基本とする。UIは正式化やreconciliationの途中を「保存済み」と表示しない。

既存の完成MP4が存在する場合は黙って上書きしない。ファイル名と衝突時の具体的な操作は未決定とし、第19開始前までに正式決定する。

`save_state.json` を検証できない場合は保存済み件数を推測表示しない。「再確認」は保存先の存在と同一性を確認する操作であり、自動保存再開を意味しない。reconciliationを含む復旧UIは第20開始前までに保存契約と合わせて正式決定する。

# その他のUIルール

## 44. 使い方

小さなSheetまたはPopover程度。

内容:

- 動画を選ぶ
- 人物を選ぶ
- 解析して良い場面を保存する

詳細技術説明は不要。

## 45. 操作できないもの

動画未選択、人物未選択、解析中、停止処理中、保存中など、状態に応じて無効な操作は最初からdisabledにする。

ただし安全性をUIだけに依存せずService側でも二重操作を防ぐ。

## 46. 状態管理

Viewから重要状態を直接変更しない。
AppViewModel等の操作メソッド経由で状態遷移させる。

`isAnalyzing`, `isSaving`, `isStopped`, `showResults` 等の排他的Booleanを大量に乱立させずenum等を使用する。

## 47. ViewとPythonの寿命

Python解析プロセスをSwiftUI Viewの `.task` 等へ直接所有させない。
画面再描画・非表示によって解析プロセスの寿命が不用意に変化しない構造にする。

## 48. 初期版で設定画面を作らない

- 保存先: 保存時に指定
- 解析方式: 固定
- モデル不足: 必要時だけ案内
- 一時ファイル: 自動管理

## 49. 初期版で実装しないUI

- CPU・メモリ表示
- 残り時間予測
- 全体進捗％
- 一時停止
- 解析中プレビュー
- 解析タイムライン
- 音声波形
- サムネイル一覧
- 星評価
- 本人確率表示
- 文字起こし画面
- 品質3モード
- 人物手動変更
- 高度フィルター
- 高度ソート
- ドラッグ＆ドロップ
- 独自ショートカット
- 完了通知
- 完了音
- 録音による人物登録
- 高度履歴
- 設定画面

## 50. UIの成功条件

- 「次に何を押すか」を考えなくても操作できる。
- 問題発生時に「次に何をするか」が画面から分かる。
- 処理中と完成を誤認しない。
- AI内部技術を意識しなくてよい。
- 長時間解析でもUIが安定する。

## 51. 最終原則

- 今必要な操作だけ見せる。
- 正常な時は静かにする。
- 問題がある時だけ目立たせる。
- AIの怪しい数値を出さない。
- 処理中と完了を分ける。
- 解析と保存を分ける。
- UIに解析ロジックを重複させない。
- 動画編集ソフトにしない。
- 便利機能より壊れにくさを優先する。
- 参考画像は見た目の参考。本体仕様を最優先する。
