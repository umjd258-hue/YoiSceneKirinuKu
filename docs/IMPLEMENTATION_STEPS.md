# 「良いシーン切りぬく〜よ」正式実装工程表

## 1. この文書の位置づけ

本書は、「良いシーン切りぬく〜よ」をCodexで段階的かつ安全に実装するための、唯一の正式な実装工程表である。

第0〜23段階、および人物関連を分割した第7A／第7B、第8A／第8B／第8Cの目的、順序、開始Gate、完了条件は本書を正本とする。`DEVELOPMENT_RULES.md` は全段階に適用する共通開発ルールであり、工程表ではない。

過去の第0〜23段階の正式な本文は現存資料で確認できなかった。そのため本書は、現在の `PRODUCT_SPEC.md`、`UI_SPEC.md`、`ARCHITECTURE.md`、`DEVELOPMENT_RULES.md`、`DESIGN_REFERENCE.md`、承認済み開発方針、準備A・準備Bの監査結果から、安全な実装順序として再構成したものである。過去の工程内容を復元したものではない。

仕様の優先順位は次のとおりとする。

1. `PRODUCT_SPEC.md`
2. `UI_SPEC.md`
3. `ARCHITECTURE.md`
4. `DEVELOPMENT_RULES.md`
5. `DESIGN_REFERENCE.md`
6. `reference-images/`

本書が上位仕様と矛盾する場合は上位仕様を優先し、本書を修正する。矛盾を実装で埋めない。

## 2. 全段階に適用する運用規則

- Codexへの1回の実装依頼は原則1段階とする。
- 第7A／第7B、第8A／第8B／第8Cも、それぞれ独立した実装単位とする。
- 前段階の完了条件を満たすまで後続段階を開始しない。
- 開始Gateがある段階は、全Gate項目を正式仕様へ反映してから開始する。
- Gate未通過時は実装せず、未決定事項と必要な検証を報告して停止する。
- 技術検証の成功だけで本体実装へ進まない。検証結果を `ARCHITECTURE.md` 等へ正式反映してから進む。
- 各段階で必要な正常系・異常系を同じ段階で実装する。第21へ先送りしない。
- `finished`、ボタン押下、要求送信、プロセス終了だけで成功扱いしない。
- partial、正式成果物、保存状態を区別する。
- 新しい依存関係は承認なしに追加しない。
- 仕様にない機能と後続段階の機能を先行実装しない。
- 各段階の完了時に、ビルド、対象テスト、既存テスト、主要エラー状態、差分、仕様外実装の有無を確認する。実行不能な確認は理由を報告する。

## 3. 未決定事項の扱い

本書に「正式決定する」と記載した事項は、そのGateまで未決定である。実装を容易にする目的で仮の方式や数値を採用してはならない。

特に、AI閾値、複数sampleのEmbedding統合方式、Source fingerprint方式、App Sandbox採否、Python／FFmpeg／AIモデルの配置・同梱方式、停止signal、停止猶予時間、強制終了方式、停止完了event形式、保存ファイル名形式、衝突解決方式、Security-Scoped Bookmark採否、スリープ抑止方式は、指定Gateで技術検証結果をもとに正式決定する。

# 第0段階：技術成立性検証と開発前提の確定

## 前提・参照

- 全仕様書
- `ARCHITECTURE.md` の技術検証項目
- `DEVELOPMENT_RULES.md` の依存関係・技術検証ルール

## 今回の目的

本体へ不確実な実行方式を組み込む前に、macOS上で必要となる技術要素を小さな実験として検証し、後続Gateで判断できる記録を作る。

## 開始Gate

- 検証ごとに目的、対象、成功条件、失敗時の扱い、作成する実験コードの範囲が承認されている。
- 新しい依存や外部バイナリが必要な場合は、追加前に承認されている。
- 本体コードへ実験実装を混入させない方針が確認されている。

## 実装すること

- `experiments/` に分離した最小検証を、1検証ずつ実施する。
- App Sandboxあり／なしの成立性を比較する。採否は検証前に決めない。
- SwiftからPython subprocessを起動し、終了状態とstdout／stderrを分離できるか検証する。
- PythonからFFmpegを引数配列で起動できるか検証する。
- 開発時に使用するPython、FFmpeg、AIモデルの候補配置で完全ローカル処理が成立するか検証する。
- 外部SDカードの読み書き、切断、再接続を検証する。
- Source fingerprint候補方式の成立性とコストを測定する。
- cooperative stop、FFmpeg等の子プロセス終了候補を検証する。
- 多重起動・二重解析防止候補を検証する。
- Security-Scoped Bookmarkとスリープ抑止の必要性・成立性を検証する。採否はこの記述だけで確定しない。
- 検証結果、制約、未決定事項、後続Gateへの入力を記録する。

## 実装しないこと・重要制約

- 本体機能を実装しない。
- 実験コードを本体へコピーして完成扱いしない。
- App Sandbox、同梱、signal、猶予時間等を検証前に決めない。
- App Store配布を前提にしない。
- 外部APIやクラウド処理を追加しない。

## 完了条件

- 第1段階に必要な技術成立性が確認され、再現可能な結果が記録されている。
- 第1段階で使用しない未検証・未決定事項は、対応する後続段階の開始Gateと「実装者が推測で確定してはならない」ことが明示されている場合に限り、後続Gateへ繰り延べられる。
- 上記を満たす場合、後続Gateへ繰り延べた項目が未検証・未決定のまま残っていても、第0段階を完了できる。繰延べは検証済みまたは採用決定を意味しない。
- 後続段階で必要となる決定事項と期限が整理されている。
- 採用判断が必要な事項は、対応する上位仕様へ反映する準備ができている。

## 後続Gateへ繰り延べる未検証・未決定事項

- App Sandbox採否は、ファイル選択・subprocessへ影響する場合は第3開始前、最終採否は第22開始前までに決定する。有効な開発署名によるSandboxありの再検証は未実施のまま維持する。
- Preflightに必要なPython／FFmpegの開発時配置は第3開始前までに決定する。Python／FFmpeg／AIモデルの完成版配置・同梱方式は第22開始前までに決定する。
- Source fingerprintの正式方式と、多重起動・二重解析防止方式は、候補検証結果をもとに第9開始前までに決定する。
- スリープ抑止の必要性は第9開始前、最終採否と解除契約は第22開始前までに決定する。
- 人物登録サンプルの品質条件および適切な長さは、第8A／第8B開始前までに技術検証結果をもとに決定する。
- 停止signal、猶予時間、強制終了条件、Process groupおよび停止完了event形式は第14開始前までに決定する。
- 外部SDカードの書込み途中の切断、再接続、partial復旧およびreconciliationは第20開始前までに検証・決定する。通常接続状態以外は未検証のまま維持する。
- Security-Scoped Bookmarkの最終採否は、App Sandboxと外部保存先アクセスの方針を踏まえて第22開始前までに決定する。

## テスト・確認

- 各実験を単独で実行し、成功・失敗双方を記録する。
- stdoutへ通常ログが混入しないことを確認する。
- 元動画や完成成果物を書き換えていないことを確認する。
