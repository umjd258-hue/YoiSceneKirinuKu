# ORIGINAL_SCOPE_CONTRACT.md — 初期版の固定スコープ

この文書は、仕様追加によって初期版の目的が膨張・変質することを防ぐ。

## 初期版の正式入力
- 正式対応動画は MP4 を基本とする。
- MOV/MKV等を初期版の正式対応へ勝手に追加しない。
- 他形式対応は将来の独立した仕様変更とする。

## 解析と保存
- 解析結果を表示しただけでは動画を保存しない。
- ユーザーが結果一覧で明示的に選択した候補だけ保存する。
- 自動で全候補を書き出さない。
- 完成済みMP4をアプリが勝手に削除しない。

## 人物登録資産
人物sampleの登録元音声 `source.wav` は重要な再生成元資産として保持する。
Embeddingはmodel/version変更時に再生成できるが、source.wavをcleanup対象として勝手に削除しない。

## 品質表示
初期版のユーザー向け品質表示は原則3段階:
- ◎ 良い
- ○ 使用可能
- △ 注意

表示には可能な範囲で簡潔な理由codeを付ける。
例: overlap / bgm / se / noise / clipped / low_confidence。
正式な判定方法・閾値はStage Gateで検証する。

## 初期版で行わない
- 人物の自動発見
- 人物不明候補の自動クラスタリング
- 常時文字起こし/ASR
- 専用BGM/SE分類AIの無検証追加
- 音源分離を必須処理にすること
- 複雑な自動キャッシュ
- 複数動画の並列解析
- 常駐Python daemon
- 根拠のない自動閾値決定
- cloud AI/APIへの動画・音声送信

## 軽量性
- 解析ジョブは原則同時1件。
- Pythonは必要な処理単位で起動し、常駐させない。
- DBを初期版の必須依存にせず、JSON＋フォルダを基本とする。
- SDカードへの中間書込を必要最小限にし、可能な解析中間物はMac側workspaceを利用する。
- 重いモデルは必要時のみloadし、処理後に解放できる構造を優先する。
- 長尺動画は全データを一括RAM保持せずchunk/stream処理可能な構造にする。

## 停止
「停止要求を受け付けた状態」と「実際に停止完了した状態」を区別する。
UIが停止要求直後に完了扱いしない。
