# Source fingerprint候補比較検証結果

## 総合判定

プロジェクト内の人工ファイルだけを使用し、5候補の変更検出能力、見逃し、処理時間および読取り量を比較できた。実験は同一条件で2回完了し、いずれも機械検証に成功した。

全体SHA-256は今回の全内容変更ケースを検出した。サイズ、更新時刻、部分SHA-256にはそれぞれ見逃すケースがあった。この結果は第9開始Gateの判断材料であり、本番方式または本番パラメータの決定ではない。

## 実験条件

- 人工ファイル: 1 MiB、64 MiB、256 MiB
- 部分SHA-256: 先頭、中央、末尾から各64 KiB
- 処理時間: 各サイズ・各方式5回
- Python標準ライブラリのみ
- 外部アクセス、外部依存、ユーザー動画、外部ストレージは不使用

ファイルサイズ、部分読取り位置、64 KiB、反復回数その他の値は検証専用であり、本番仕様として採用しない。処理時間はOSファイルキャッシュの影響を含む今回の環境の値であり、cold-cache性能または他環境の性能へ一般化しない。

## 処理時間と読取り量

次は2回目の実験における初回値／後続4回の中央値である。

| 方式 | 読取り量 | 1 MiB | 64 MiB | 256 MiB |
|---|---:|---:|---:|---:|
| サイズ | 0 bytes | 0.003／0.001 ms | 0.002／0.001 ms | 0.004／0.001 ms |
| サイズ＋mtime | 0 bytes | 0.001／0.001 ms | 0.001／0.001 ms | 0.002／0.001 ms |
| サイズ＋mtime＋部分hash | 196,608 bytes | 0.085／0.077 ms | 0.083／0.077 ms | 0.127／0.080 ms |
| サイズ＋部分hash | 196,608 bytes | 0.077／0.077 ms | 0.077／0.077 ms | 0.078／0.078 ms |
| サイズ＋全体hash | ファイル全体 | 0.360／0.337 ms | 24.183／23.834 ms | 94.553／94.587 ms |

部分hashの読取り量は今回の3領域×64 KiBではファイルサイズにかかわらず196,608 bytesだった。全体hashはファイルサイズに比例して全bytesを読み取った。

## 各候補の評価

### サイズ

最小コストだが、同一サイズの内容変更をすべて見逃した。単独で元動画の同一性を保証できない。

### サイズ＋更新時刻

通常の書込みでmtimeが変わるケースは低コストで検出した。一方、mtimeを復元した変更と、同一サイズ・同一mtimeの置換を見逃した。mtime変更だけでも不一致になる。

### サイズ＋更新時刻＋部分SHA-256

今回の通常変更と同一メタデータの全面置換を低い読取り量で検出した。一方、部分hash範囲外を変更してmtimeを復元したケースを見逃した。完全な内容同一性確認にはならない。

### サイズ＋部分SHA-256

mtimeだけの変化には影響されず、サンプル範囲内の変更を低コストで検出した。一方、読取り範囲外の変更を見逃した。

### サイズ＋全体SHA-256

今回の全内容変更を検出し、mtimeだけの変更は内容変更として扱わなかった。検出能力は最も高い一方、ファイル全体のI/Oとハッシュ計算が必要で、実ファイルが大きいほどコストが増える。

## 推奨候補

- 内容同一性を最優先する候補: サイズ＋全体SHA-256
- 軽量な事前確認候補: サイズ＋更新時刻、またはサイズ＋更新時刻＋部分SHA-256
- 段階的確認候補: 軽量fingerprintを高速な不一致検出に使い、正式な再利用可否に全体SHA-256を要求する構成

ただし、軽量fingerprintが一致した場合に全体hashを省略すると、今回確認したmtime復元・部分範囲外変更を見逃す。どのリスクを許容するか、fingerprintをいつ計算するか、解析開始時と再開時のどちらで全体hashを要求するかは第9開始Gateで決定する。

## 第9開始Gateへ残す事項

- Source fingerprintの正式な構成フィールドとschema
- 全体hashを必須にするか、段階的確認を許容するか
- 対応する実動画サイズと保存媒体でのI/Oコスト
- SDカード上の大容量動画での性能と切断時の扱い
- fingerprint計算中に元ファイルが変更された場合の検出・再試行契約
- ファイル置換、inode等の追加メタデータを扱うか
- hash algorithmとversion管理
- fingerprint保存先、所有者、検証時点、失敗時の状態遷移

今回の結果だけでSource fingerprint方式を正式決定しない。
